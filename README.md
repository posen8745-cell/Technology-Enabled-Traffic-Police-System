[開啟互動網站](https://posen8745-cell.github.io/Technology-Enabled-Traffic-Police-System/) · [個人學習歷程](https://posen8745-cell.github.io/posen-learning-portfolio/)

## 從生活中發現問題

上下學經過家附近 T 字路口時，我常看到車輛排隊。我想到：如果車多的方向還在等紅燈，另一邊只有少量車輛，能不能讓程式根據車流調整綠燈時間？

但只說「車多就延長」還不完整。我也想知道何時該停止延長、讓另一邊通行，因此提出加上路口車流量監測器，讓判斷依據與換邊原因可以在畫面上看到。

這是 HTML、CSS、JavaScript 與 Canvas 的軟體模擬。所有車流、監測與號誌都是程式資料，目前沒有接真實攝影機、感測器或交通號誌。

## 我的參與與 AI 分工

我提出生活觀察、路口情境與功能需求，查看畫面後繼續提出修改；網頁、動畫、程式、測試及文件草稿由 AI 完成。目前不是我獨立寫完全部程式。

| 我提出的問題或需求 | 程式中的修改 |
| --- | --- |
| 要保留原本車輛與 T 字路口 | 保留路口、車道、斑馬線、直行與連續轉彎動畫 |
| 畫面車輛太多，但後方可能有 50 輛 | 左方顯示前 3 輛、右方前 5 輛，後方車隊完整保存在資料中 |

## 如何操作

1. 開啟網站，選主線初始車隊 **7、20 或 50 輛**。改選或重新示範會重置兩種模型。
2. 先看固定秒數，再按 **「啟動程式疏導」**。啟動時間由程式記錄。
3. 看路口下方的 **「路口車流量監測器」**，留意每個方向的待通行車數和紅燈停等。
4. 看右側綠色判斷框及下方「最近的程式判斷」：車隊還在就可能延長；清空、達上限、另一邊等太久就換邊。
5. 按 **「切換看固定秒數」／「切換看程式疏導」**，查看同一模擬時刻的路口和監測資料。切換畫面不會重啟模型。
6. 可暫停、繼續，或選 1、3、6 倍速。全部秒數是模擬時間，倍速會縮短實際觀看時間。
7. 按 **「下載本次監測 CSV」** 保存當下兩個模型的數值；頁面學習紀錄另附固定條件的驗證比較表下載。

模擬最長 600 秒，結束後仍可切換畫面與下載資料。使用系統「減少動態效果」時初始暫停，可按「繼續」。

## 什麼時候延長，什麼時候換邊？

| 判斷 | 程式怎麼做 |
| --- | --- |
| 剛變綠燈 | 主線先給 6 秒、支線先給 10 秒，未滿最短綠燈不提早換邊 |
| 仍有待通行車輛，其他方向未連續紅燈停等 45 秒 | 原本核給時間到期後，每次延長 3 秒，最後一次可能少於 3 秒，以遵守上限 |
| 目前方向已無待通行車輛 | 滿最短綠燈後，結束綠燈，準備換邊 |
| 目前綠燈達上限 | 主線最多 55 秒、支線最多 22 秒，停止延長 |
| 別的方向連續紅燈停等達 45 秒 | 滿最短綠燈後停止延長，準備讓等太久的方向通行 |
| 決定換邊 | 3 秒黃燈、至少 3 秒全紅；路口有車就延長全紅 |
| 選下一方向 | 等太久且有車的方向優先，若同時達門檻則選連續紅燈停等較久者；其餘有車方向依下方、左方、右方輪流，無車方向略過 |
| 各方向都沒有車 | 全紅待命，有來車才選下一方向 |

**45 秒是觸發換邊的門檻，不保證第 45 秒就變綠燈，更不保證每輛車在 45 秒內通過。** 還要完成最短綠燈、黃燈、全紅及清空；長車隊也可能等不只一輪。上述秒數為展示控制想法的模擬參數，不是真實路口工程設計值。

右側「本次核給剩餘」是目前已分配的秒數，可能繼續延長，不是確定的最終倒數。放行途中啟動程式時，保留已過的綠燈時間，依最短與最長綠燈重新判斷；若在黃燈或全紅中啟動，先完成過渡。

固定秒數模型仍依下方、左方、右方輪流，綠燈分別為 22、14、14 秒，保留相同黃燈、全紅及路口清空規則。

## 監測器的數值代表什麼？

| 數值 | 定義 |
| --- | --- |
| 待通行 | 尚未獲放行的所有車輛，包含接近車隊中的來車與畫面外的後方車輛 |
| 當下停住 | 目前模型時間步中沒有向前移動的待通行車輛 |
| 近 60 秒到車 | 滑動時間窗 `(目前時間−60, 目前時間]` 內的新到車輛，不含起始車隊；未滿 60 秒只計已過時間 |
| 紅燈停等最久 | 該方向目前車輛「連續停住且未獲綠燈」的最長時間，用來判斷換邊；移動或獲綠燈後歸零 |
| 平均停等 | 自起始到目前全部車輛的累積停住時間，除以全部已到達車輛數，包含未放行與零停等車輛 |
| 最久停等 | 自起始到目前任何一輛車的累積停住時間最大值；包含已放行車輛，跨多輪累加 |
| 已放行 | 已從待通行車隊越過停止線獲放行的數量，並不是全部已離開路口的數量 |

平均停等不是行程時間，也不是只計已完成旅程的車。紅燈停等和累積停等是不同指標。畫面監測資料跟隨目前所選模型；整段停等比較始終並列兩種模型。

## 車流與公平比較

| 起始主線總數 | 左方來車 | 右方來車 | 下方支線 |
| ---: | ---: | ---: | ---: |
| 7 | 2 | 5 | 2 |
| 20 | 6 | 14 | 2 |
| 50 | 16 | 34 | 2 |

50 輛情境右側包含 23 輛左轉、11 輛直行。後續右側來車以三分之二機率設定為左轉；左側直行保留約半數。兩個模型使用同一份固定種子的到車及轉彎資料，不會因啟動疏導而減少來車。每次重新示範能重現相同車流；600 秒內各加入 138 輛新車。

## 程式檢查與新版結果（2026/11/23）

AI 協助執行實際網頁程式的模型檢查：啟動前一致、車數守恆、停等合計一致、各方向分時綠燈、黃燈及全紅清空、最短與最長綠燈、延長、清空提早換邊、等待優先、近 60 秒到車邊界、行進時不累加停等，以及各種燈號中途啟動。

## 反思與下一步

這次讓我注意到，延長綠燈也要有停止的理由。車數可以反映需求，等待時間則提醒我不能一直照顧車多的一邊。把監測、判斷、切換原因與對照資料放在一起，才比較容易解釋程式在做什麼。

我接下來要自己操作三種車隊情境，保存同一時點的畫面與 CSV，練習用自己的話解釋延長及換邊原因。目前這份個人操作紀錄仍待補上。

目前限制：

- 車流、比例、速度、車距與放行間隔都是示範設定，沒有現地量測。
- 未模擬完整駕駛反應、加減速、變換車道、下游堵塞與相鄰路口。
- 各方向分時放行，沒有模擬同時綠燈下左轉禮讓。
- 畫面保留斑馬線與行人號誌，但行人維持停止，沒有實作行人通行時段。
- 模型與號誌檢查不等於完整軌跡碰撞驗證或真實道路安全驗證。
- 新增監測器目前讀取模擬資料，沒有完成實體感測器與真實號誌控制。

後續可加入更多到車情境、各方向最大車隊、下游堵塞與行人時段，再研究實際車流偵測方式。
