# T 字路口車流監測與紅綠燈控制模擬

基隆私立二信高中｜普通科數理班｜P2C29｜張博程

我提出想法、路口情境和修改需求，網頁、動畫與程式由 AI 完成。

[開啟模擬網站](https://posen8745-cell.github.io/Technology-Enabled-Traffic-Police-System/) · [個人學習歷程](https://posen8745-cell.github.io/posen-learning-portfolio/)

## 為什麼想做這個作品？

上下學經過家附近的 T 字路口時，我常看到汽車排隊。有時車多的方向還在等紅燈，另一邊卻沒有多少車。我想到，如果能知道各方向有幾輛車，是不是可以讓車多的方向多通行幾秒？

一開始，我只想到延長綠燈。後來討論時才發現，還要回答另一個問題：什麼時候該停止延長，讓另一邊通行？如果只看哪邊車多，車少的方向也可能一直等。

所以這個作品除了調整綠燈，也加上車流量監測器，把車數、等待時間和換邊原因顯示出來，讓我能看懂程式根據什麼做決定。

## 這一版先模擬什麼？

**先以汽車為對象，假設路口出口暢通，比較固定秒數和依車流調整號誌的停等差異。**

畫面保留 T 字路口、汽車、直行與轉彎。機車和行人通行先不納入；畫面中的行人號誌維持停止。車流量監測器目前讀取程式產生的資料，還沒有接攝影機、實體感測器或真正的紅綠燈。

## 我負責哪些部分？

我主要負責描述家附近的路口、提出功能需求，並查看畫面、指出需要修改的地方。網頁、動畫、控制程式、測試程式和這份說明的草稿由 AI 完成。目前我還沒有獨立寫完全部程式，這個作品主要記錄我如何提出問題、回饋修改，以及理解控制規則。

| 我提出的問題 | 後來怎麼修改 | 檢查什麼 |
| --- | --- | --- |
| 要看得到原本的車輛和 T 字路口 | 保留車道、斑馬線、直行與轉彎動畫 | 是否看得出車從哪裡來、往哪裡走 |
| 車太多看不清楚，但後方可能還有 50 輛 | 左方顯示前 3 輛、右方前 5 輛，其餘用數字標示 | 畫面外的車有沒有算進去 |
| 左側直行較少，右側左轉較多 | 調整左右來車和轉彎比例 | 50 輛情境右側有 23 輛左轉、11 輛直行 |
| 右方左轉會和左方直行交會 | 各方向分時放行，切換時先黃燈、全紅 | 路口有車時，下一方向是否繼續等候 |
| 只說延長綠燈，還是不清楚何時換邊 | 加入監測器、等待門檻與判斷紀錄 | 車隊清空、達上限或另一邊等太久時，是否停止延長 |
| 光看某一刻車變少，還不能知道有沒有改善 | 用相同車流比較兩種控制，記錄平均與最久停等 | 有沒有同時看主線、支線和整段停等 |

## 可以怎麼操作？

1. 選擇主線起始車隊 **7、20 或 50 輛**，先看固定秒數如何放行。
2. 按 **「啟動程式疏導」**，查看綠色判斷框和路口下方的 **「路口車流量監測器」**。
3. 留意「最近的程式判斷」，看它為什麼延長綠燈，或為什麼準備換邊。
4. 切換 **「固定秒數」與「程式疏導」**，比較同一模擬時刻的車隊和停等數值。切換畫面不會重新開始。
5. 需要記錄時先暫停，再按 **「下載本次監測 CSV」**，保存當下兩種控制的數值。

可以選擇 1、3、6 倍速。畫面上的秒數都是模擬時間；例如 3 倍速就是用較短的實際時間觀看模擬。每次最長模擬 600 秒，結束後仍可切換和下載資料。改選車隊或按「重新塞車示範」會重新開始；系統啟用「減少動態效果」時，初始暫停，可按「繼續」。

## 程式什麼時候延長，什麼時候換邊？

程式會每秒檢查，但剛變綠燈時會先保留一段最短放行時間，避免才放行就馬上切換。

| 情況 | 做法 |
| --- | --- |
| 剛變綠燈 | 主線先給 6 秒、支線先給 10 秒 |
| 時間用完，這邊還有車，而且別的方向未連續停等滿 45 秒 | 每次再給 3 秒；接近上限時，最後一次可能少於 3 秒 |
| 這邊已沒有待通行的車 | 滿最短綠燈後，準備換邊 |
| 綠燈已到上限 | 主線最多 55 秒、支線最多 22 秒，停止延長 |
| 別的方向連續停等達 45 秒 | 滿最短綠燈後停止延長，準備讓等太久的方向通行 |
| 要換邊 | 先 3 秒黃燈，再至少 3 秒全紅；路口仍有車就繼續等 |
| 決定下一個方向 | 達等待門檻的方向優先；若不只一個，就選等較久的。其餘有車方向依下方、左方、右方輪流，沒有車的方向略過 |
| 各方向都沒有車 | 全紅待命，有來車再放行 |

這裡的「連續停等」是汽車停住、沒有獲得綠燈的時間。**45 秒是提醒程式準備換邊的門檻，不是每輛車都能在 45 秒內通過。** 切換還需要黃燈、全紅和清空時間，長車隊也可能等不只一輪。

固定秒數的版本依下方、左方、右方輪流，綠燈分別是 22、14、14 秒；兩個版本都有黃燈、全紅和清空路口的規則。這些秒數都是模擬設定。

## 用相同車流比較，結果如何？

兩個版本的起始車隊、後續來車、轉彎路線和通行速度相同，按下疏導不會讓新來的車變少。每次重新示範都能重現相同車流；600 秒內，每個版本各加入 138 輛新車。

以下保留 **2026/11/23 由 AI 協助執行的程式模擬檢查結果**。每種情境都先跑 30 秒，再啟動程式控制，到第 600 秒比較。這是程式產生的數據，我自己的操作截圖與說明還待補上。

| 起始主線 | 固定主線待通行 | 程式主線待通行 | 固定支線待通行 | 程式支線待通行 | 固定已放行 | 程式已放行 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 7 | 1 | 3 | 3 | 0 | 143 | 144 |
| 20 | 1 | 3 | 3 | 0 | 156 | 157 |
| 50 | 10 | 3 | 3 | 0 | 177 | 187 |

上表的車數單位為輛。「已放行」是已從車隊獲放行的車輛，不代表全部都已離開路口。

| 起始主線 | 固定平均停等（秒） | 程式平均停等（秒） | 固定最久停等（秒） | 程式最久停等（秒） |
| ---: | ---: | ---: | ---: | ---: |
| 7 | 21.1 | 13.4 | 52.7 | 46 |
| 20 | 30.9 | 16.9 | 115 | 57 |
| 50 | 81.8 | 34 | 243.1 | 126.8 |

平均停等把所有已到達的車都算進去，包含還在等的車和沒有停等的車；最久停等則是單輛車累積停住時間的最大值，可能跨好幾輪燈號。

這三組資料中，程式控制的平均停等較少。不過，7 輛和 20 輛情境在第 600 秒的主線待通行車數反而較多。50 輛情境也仍有車累積停等 126.8 秒。這提醒我，不能只看一張車隊變短的畫面，就說所有方向都改善了。

## 這次整理後，我想繼續了解什麼？

我原本只想到，車多的方向就多給幾秒綠燈。後來才發現，如果一直延長，另一邊也可能越等越久，所以還要設定換邊條件。加上監測器之後，可以從畫面對照車數、等待時間和程式做決定的原因。

下一步，我想自己操作 7、20、50 輛三種情境，記下啟動時間，保存同一時點的畫面與 CSV，再用自己的話解釋結果。除了看車隊長短，也要一起看支線和停等時間。

目前汽車使用固定的速度、車距和放行間隔，還沒有完整模擬駕駛反應、加減速、變換車道和前方道路塞住的情況。程式已做燈號和計數檢查，但所有轉彎軌跡的碰撞驗證仍未完成。這一版先用來討論號誌控制的想法，還不能用來保證真實路口的效果。

### 監測數值怎麼看？

| 畫面名稱 | 意思 |
| --- | --- |
| 待通行 | 還沒獲放行的車，包括正在接近車隊和畫面外的後方車輛 |
| 當下停住 | 這個模擬時間步中，沒有向前移動的待通行車輛 |
| 近 60 秒到車 | 最近 60 秒新加入的車，不含起始車隊；未滿 60 秒只計已過時間。時間區間是 `(目前時間−60, 目前時間]` |
| 紅燈停等最久 | 該方向汽車連續停住、且沒有獲綠燈的最長時間，包含黃燈和全紅的未放行時間；車子移動或獲綠燈後歸零 |
| 平均停等 | 全部已到達車輛的累積停住時間，除以車輛數，包含還沒放行和零停等的車 |
| 最久停等 | 從模擬開始到目前，任何一輛車累積停住時間的最大值，包含已放行的車 |
| 本次核給剩餘 | 目前已分配、還沒用完的秒數，之後可能繼續延長 |

平均停等不是行程時間。「紅燈停等最久」用來判斷換邊，「最久停等」則是整段累積，兩個數字不同。監測表會跟隨目前選擇的畫面；停等比較表始終並列兩個版本。

在綠燈途中啟動程式，已過的時間仍保留，接著依最短、最長綠燈判斷；在黃燈或全紅中啟動，則先完成過渡。

### 起始車隊

| 起始主線總數 | 左方來車 | 右方來車 | 下方支線 |
| ---: | ---: | ---: | ---: |
| 7 | 2 | 5 | 2 |
| 20 | 6 | 14 | 2 |
| 50 | 16 | 34 | 2 |

左側直行減量後，減少的車數配置到右側，維持選定的主線總數。50 輛情境右側有 23 輛左轉、11 輛直行；小車隊受整數分配影響，不一定接近 2：1。後續右側來車以三分之二機率設定為左轉，左側直行保留約半數。

### 程式檢查

檢查內容包括：啟動前兩版本一致、相同到車資料、車數與停等時間合計、分時綠燈、黃燈與全紅清空、最短與最長綠燈、延長與提早換邊、等待優先、近 60 秒到車的時間邊界，以及不同燈號中途啟動。

使用 Node.js 可重跑檢查，不用安裝額外套件：

```sh
node tests/traffic-model.test.cjs
```
